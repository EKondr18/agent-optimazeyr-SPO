# Агенты разработки продукта

Четыре роли ведут разработку и проверку оптимизатора распределения задач СПО.
Каждая роль описана отдельным файлом (`analyst.md`, `programmer.md`, `tester.md`,
`devops.md`) и запускается как субагент Claude Code.

## Как они передают работу

```
аналитик ──задача с цифрами──▶ программист ──ветка──▶ тестировщик ──зелёные проверки──▶ девопс ──предпросмотр──▶ человек ──▶ main
    ▲                                                                                                           │
    └──────────────────────── новые выгрузки, замеры, отчёты ◀──────────────────────────────────────────────────┘
```

1. **Аналитик** принимает данные и замеры и формулирует проблему с цифрами
   (что, на каких днях, насколько хуже/медленнее, что это даст).
2. **Программист** делает минимальную правку под эту задачу.
3. **Тестировщик** доказывает, что правка не ломает правила и результаты
   (тесты, сравнение «до/после» на одних и тех же данных).
4. **Девопс** следит, чтобы проверки выполнялись автоматически на каждое
   изменение и чтобы выкладка не ломала открытые страницы.
5. **Человек** (владелец продукта) принимает решения по правилам и сливает в `main`.

## Общие правила для всех ролей

- **Решения по правилам не принимает ни один агент:** допуски, допустимая
  переработка, отдых между сменами, параллельные задачи одного рейса, замена
  допусков — только предложение с цифрами.
- **Жёсткие ограничения не ослабляются ради результата:** допуски (все
  требуемые), отсутствие пересечений, смена и переходы между стоянками. Любой
  план проходит `validatePlan`.
- **Расчёты детерминированы:** одинаковые данные и seed дают одинаковый
  результат. Ускорение не должно менять результат; если меняет — это
  отдельное решение с объяснением.
- **Реальные данные не попадают в репозиторий:** ни ФИО сотрудников, ни
  идентификаторы, ни выгрузки целиком. В отчётах — только агрегаты. Для CI —
  синтетические данные.
- **Агенты не делают `git commit`/`git push`:** это делает оркестратор
  после проверки результатов всех ролей.
- **Каждое утверждение — с проверкой:** запуск, цифра, тест. «Должно
  работать» не принимается.
- **Отчёт агента:** что сделано, какие файлы изменены, что запускалось и с каким
  результатом, чего не удалось сделать и почему.

## Проверки

- `cd web_app && npm test` — все тесты должны проходить.
- `cd web_app && npm run build` — сборка без ошибок.
- Замер и проверка интерфейса — см. `web_app/bench/README.md`.
