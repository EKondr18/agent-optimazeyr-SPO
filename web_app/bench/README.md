# Замер и проверка интерфейса

Всё запускается из `web_app/`, данные по умолчанию синтетические (в репозитории нет ни ФИО, ни идентификаторов).
Node 22, зависимостей, кроме проектных, нет (Playwright нужен только для `bench:ui`).

| Команда | Что делает | Время |
|---|---|---|
| `npm run bench` | `bench/run.mjs`: планировщик на синтетических днях, таблица, сравнение с `bench/baseline.json` | см. ниже |
| `npm run bench:determinism` | `bench/determinism.mjs`: один вход — один результат, в том числе в трёх часовых поясах | см. ниже |
| `npm run bench:ui` | `bench/ui-smoke.mjs`: страница в браузере (Playwright) в трёх часовых поясах | сборка + ~1 мин |

## `npm run bench`

Генератор `bench/synthetic.mjs` (фиксированный seed; все даты по Москве через `src/utils/tz.js`):
~100 человек на смене в день (дневные 10–23, 08–17, ночные 20–09, у людей 0–8 допусков, SV у ~30 %),
400–700 задач в день с профилем по часам, допуски задач как в реальных выгрузках
(B-737NG ~38 %, SV ~25 %, A-320 ~20 %, SSJ ~9 %, B-737CL ~4 %, A-330 ~3 %), допуск `SPO_CRJ` (~1 % задач), которого нет ни у кого,
~2 % задач с двумя допусками, 1 % аномальных задач длиннее 12 ч, 60 стоянок (6 не в таблице локаций),
сеть переходов 6×5 узлов. Данные берутся на день до первого и день после последнего замеряемого дня (окно расчёта — три дня).

Для каждого дня и каждого режима (`lns0` — без LNS; `default` — как кнопка «Запустить оптимизатор») печатается: задач, нераспределённых
за день, нижняя граница, разрыв, ходьба (м), переработка и недостаток запаса (мин), нарушения, время по этапам. Код выхода 1, если:

* есть нарушение правил (`stats.violations` или `validatePlan` по диапазону день−2 … день+2);
* нераспределённых меньше нижней границы — это ошибка (граница — доказательство);
* поиск оборван часами (`timeCut`) — результат невоспроизводим;
* во входе есть непригодные задачи (`stats.invalid`);
* нераспределённых за день больше эталона на допуск (по умолчанию большее из «+2» и «+5 %»; `--tol-abs`, `--tol-pct`).

Время в сравнение не входит. Эталон — `bench/baseline.json` (создан на `--seed 1 --days 3`); он хранит версию генератора
(`GENERATOR_VERSION` в `synthetic.mjs`) и настройки; при несовпадении замер отказывается сравнивать (код 2).
Если вы сознательно изменили поведение планировщика (или генератор): `node bench/run.mjs --update-baseline` — эталон не обновится, если в прогоне есть нарушения.

```
node bench/run.mjs --days 5 --seed 2 --out /tmp/result.json     # свои параметры, полный результат в файл
node bench/run.mjs --baseline bench/baseline.json --modes lns0   # только быстрый режим
node bench/run.mjs --update-baseline                              # записать эталон по текущему коду
```

### Реальные данные (только чтение)

`BENCH_REAL_DIR=/путь/к/папке node bench/run.mjs --days 3` (или `--dates 2026-09-13,2026-09-20`). В папке по одному CSV каждого вида
(`tb_sub_orders`, `tb_shifts`, `tb_resources`, `tb_res_qual`, `tb_relation_resource_qualification`, `tb_relation_shift_qualification`;
по имени; если подходящих несколько — берётся самый большой) и, по желанию, `tb_locations.csv` и сеть (`VKO_TRANSPORT…xlsx` или CSV).
Без `--dates` берутся самые загруженные дни, у которых есть смены и в соседних днях. В этом режиме ничего не сохраняется:
`--out`, `--baseline`, `--update-baseline` отклоняются; в таблице только числа, без имён людей и идентификаторов. Файлы и результаты не коммитить.

## `npm run bench:determinism`

На фиксированном синтетическом дне: `planWindow` дважды и `applyChanges` дважды (пакет из 20 изменений, фиксированный `now`) с настройками
по умолчанию — хэши назначений должны совпасть; те же хэши в дочерних процессах под `TZ=UTC`, `Europe/Moscow`, `America/Los_Angeles`.

Для правки, которая **не должна** менять результат (ускорение): до правки `node bench/determinism.mjs --save`, после — `node bench/determinism.mjs --check`
(файл `bench/determinism.hashes.json` локальный, в репозиторий не входит; можно указать свой путь: `--save путь`, `--check путь`).

## `npm run bench:ui`

Собирает страницу во временную папку (папка `dist` проекта не трогается; `--dist папка` — взять готовую, `--no-build` — не собирать),
поднимает `vite preview` на порту 4184 (`BENCH_UI_PORT`; если занят — на свободном) и останавливает только свой процесс. В Chromium
загружает 6 синтетических CSV (+ локации и сеть), выбирает день, «Запустить оптимизатор», раскрывает «Нехватка персонала», «Применить план»
(в окне подтверждения — «Применить»). Проверяет: нет ошибок консоли и страницы, нет неудачных запросов, нет тостов «Не удалось» / «ошибка» / `error`,
нет `NaN`/`undefined`/`Infinity` на странице, «Задач дня» равно числу задач дня в данных, «Не назначено» после плана не выросло, и **числа одинаковы
в трёх часовых поясах браузера** (UTC, Europe/Moscow, America/Los_Angeles). Печатает время этапов. При падении скриншоты и лог — в `UI_SMOKE_OUT`
(по умолчанию `<tmp>/spo-ui-smoke`).

Селекторы завязаны на тексты: «Загрузить CSV вручную», «Локации и сеть», кнопка «Загрузить», плитки (`.ant-statistic`: «Задач дня», «Не назначено»),
«Запустить оптимизатор», «Нехватка персонала», «Применить план», в окне — «Применить». Если интерфейс переименует их, правьте `ui-smoke.mjs`.

Playwright: берётся `/opt/node22/lib/node_modules/playwright` (или `PLAYWRIGHT_MODULE`), иначе пакет `playwright` из `node_modules`. Браузер:
`PLAYWRIGHT_CHROMIUM_PATH`, иначе `/opt/pw-browsers/chromium`, иначе установленный Playwright. На чистой машине:
`npm install --no-save playwright@1.56.1 && npx playwright install --with-deps chromium` (в `package.json` Playwright не добавляется).

## Файлы

* `synthetic.mjs` — генератор (`generate`, `toCsvFiles`), `GENERATOR_VERSION`;
* `lib.mjs` — разбор аргументов, хэш назначений, таблица, чтение папки с реальными выгрузками;
* `run.mjs`, `determinism.mjs`, `ui-smoke.mjs` — сами проверки; `baseline.json` — эталон.
